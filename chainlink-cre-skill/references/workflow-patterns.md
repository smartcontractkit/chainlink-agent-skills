# Workflow Patterns

Use for the trigger/callback model, generated configuration, secrets, DON Time, randomness, and handler composition. Capability-specific examples live in their references.

## Canonical handler model

A workflow registers one or more trigger/callback pairs. This file owns the base cron registration examples.

```typescript
import { CronCapability, Runner, handler, type Runtime } from '@chainlink/cre-sdk'

type Config = { schedule: string }
const onCronTrigger = (runtime: Runtime<Config>): string => {
  runtime.log(`Triggered at ${runtime.now().toISOString()}`)
  return 'done'
}
const initWorkflow = (config: Config) => [
  handler(new CronCapability().trigger({ schedule: config.schedule }), onCronTrigger),
]
export async function main() {
  const runner = await Runner.newRunner<Config>()
  await runner.run(initWorkflow)
}
```

Go's canonical registration is `cre.Handler(cron.Trigger(&cron.Config{Schedule: config.Schedule}), onCronTrigger)` inside the `cre.Workflow[*Config]` returned by:

```go
func InitWorkflow(config *Config, _ *slog.Logger, _ cre.SecretsProvider) (cre.Workflow[*Config], error) {
    return cre.Workflow[*Config]{
        cre.Handler(cron.Trigger(&cron.Config{Schedule: config.Schedule}), onCronTrigger),
    }, nil
}
```

The callback shape is `func onCronTrigger(config *Config, runtime cre.Runtime, payload *cron.Payload) (Output, error)`; the WASI entry point uses `wasm.NewRunner(cre.ParseJSON[Config]).Run(InitWorkflow)`.
Keep the entry style generated by the selected template: define/export `main` and wire its Runner, but call `main()` explicitly only when that template's entry point expects it.

For shared config/secrets/consumer state, register several handlers in one `initWorkflow`/`InitWorkflow` and instantiate each capability once. Separate workflows only for independent chains/config, lifecycle, secret namespaces, or consumer ownership.

## Generated configuration

`cre init` creates these owners; edit generated files rather than reconstructing them:

| File | Purpose |
|---|---|
| root `project.yaml` | target-wide EVM selector/RPC settings |
| workflow `workflow.yaml` | per-target workflow name, entry, config, and secrets paths |
| target config JSON | values exposed as `runtime.config` (TS) or handler config (Go) |
| root `secrets.yaml` | workflow secret IDs mapped to environment-variable names |

When a secrets/config scaffold is requested, show the concrete root `project.yaml`, workflow `workflow.yaml` entry (including the target `config-path`), target config JSON such as `config.staging.json`, root `secrets.yaml`, and `.gitignore`. Include `cre secrets list --target <target>` and route any create/update command through [operations.md](operations.md).

Example shape, not a project scaffold:

```yaml
# secrets.yaml: IDs and environment references only
secretsNames:
  MY_API_KEY: MY_API_KEY_VAR
```

```yaml
# workflow.yaml target
staging-settings:
  user-workflow:
    workflow-name: my-workflow-staging
  workflow-artifacts:
    workflow-path: ./main.ts
    config-path: ./config.staging.json
    secrets-path: ../secrets.yaml
```

Preserve target names and all user-specified schedules, units, decimals, selectors, addresses, resource IDs, and secret names across code/config/docs/simulation.

## Secret APIs

Simulation values come from an environment or `.env` consumed by the CLI; deployed values come from Vault DON. `secrets.yaml` stores no value. Lifecycle commands and custody rules are in [operations.md](operations.md).

TypeScript is synchronous and object-shaped:

```typescript
const value = runtime.getSecret({ id: 'MY_API_KEY' }).result().value
const values = runtime.getSecrets([{ id: 'KEY_A' }, { id: 'KEY_B' }]).result()
```

Never `await` or pass a bare string. Missing or unauthorized secret resolution fails; catch it only when the workflow has a real fallback. `TeeRuntime` has the same API. `NodeRuntime` has no secret provider; fetch in DON mode and pass the value as an argument to `runInNodeMode`.

Go:

```go
secret, err := runtime.GetSecret(&cre.SecretRequest{Id: "MY_API_KEY"}).Await()
```

`secret.Value` is the value. Batch with `GetSecrets([]*cre.SecretRequest{...}).Await()`.

### CRE CLI v1.1.0 secret-name substring bug

Resolution can fail with `secret not found` when the environment-variable name is a substring/prefix of the secret ID, for example `GEMINI_API_KEY` for `GEMINI_API_KEY_SECRET`. Use a non-overlapping environment name such as `GEMINI_API_KEY_VAR`:

```yaml
secretsNames:
  GEMINI_API_KEY_SECRET: GEMINI_API_KEY_VAR
```

## DON Time and randomness

Use `runtime.now()` (TypeScript) or `runtime.Now()` (Go), never `Date.now()`, `new Date()`, `time.Now()`, or other system clocks in DON mode. DON Time is a consensus median with limited resolution; do not depend on sub-second precision.

Go randomness must come from `runtime.Rand()`:

```go
source, err := runtime.Rand()
if err != nil { return nil, err }
small := source.Intn(100)
large := new(big.Int).Rand(source, new(big.Int).SetUint64(1_000_000))
```

Never use global `math/rand` or `crypto/rand` in DON mode. TypeScript has no runtime randomness API.

## Capability completion

TypeScript capability/secret/report calls return lazy handles resolved with `.result()`; they are not JavaScript promises:

```typescript
const response = httpClient.sendRequest(runtime, fetchFn, aggregation)(url).result()
const call = evmClient.callContract(runtime, options).result()
const report = runtime.report(prepareReportRequest(encoded)).result()
```

Go capability calls return `cre.Promise[T]`; `.Await()` returns `(T, error)` and drives the single-threaded event loop.

For TypeScript config validation, pass a Standard Schema such as Zod to `Runner.newRunner({ configSchema })`.

## Generation checks

- Default to TypeScript only when prompt/repository does not indicate Go.
- Use `cre init` after reading scaffolding; do not fabricate project files.
- Use regular HTTP unless request-level confidentiality is required; whole-handler confidentiality is a separate TEE capability.
- Aggregate external/node-mode results; use scaled integers/decimal strings for business values and `bigint` for Solidity integers.
- Convert `bigint` to string before `JSON.stringify`.
- Include the minimal consumer/ABI/interface/relay/mock boundary needed for a coherent integration.
- Read simulation before providing its command and always include `--target`.
